# Terrain, shadows, routing and public-surface review — 15 October 2026

Source baseline: main `a5e0ab5b80652d2823355dda591b0ce134235c5a` (0.12.0).

## Evidence and fixes

- Recomputed the lengths of all 69,769 Strassen geometries directly from the attached final EPSG:25832 GeoPackage. Median absolute difference from stored length: 0.00230 m; 95th percentile: 0.00473 m; maximum: 0.01045 m. Relative errors on very short segments are dominated by centimetre rounding. This validates arithmetic against the dataset, not real-world survey accuracy or current access conditions.
- Retrieved a real shortest-route response (Augustenstraße area), 36 pieces, reported 784.17 m. Independent WGS84-to-UTM32 transformation and polyline sum: 784.16976173 m. Difference 0.00023827 m. Recomputed ascent 16.94782152 m, descent 0.23961298 m; the adapter agrees. Time is a 13-minute estimate at 75 m/min plus one minute per 10 m ascent. It cannot be guaranteed to equal an individual's actual journey time. Access connectors, crossing waits and transient obstacles are excluded.
- A separately implemented Floyd–Warshall reference exposed zero-length endpoint handling at directed edges. At an exact start node, the engine previously forced traversing its selected one-way edge before considering alternatives. Zero-length initial/final connections now connect directly without violating any nonzero traversal direction. Thirty deterministic directed reference graphs pass.
- Weighted Shade/Sun routing previously returned an immediate same-edge route without considering a lower-cost alternative. The direct candidate now competes with the graph search. Partial endpoints and direction remain respected.
- Browser elevation profiles previously accumulated height differences from an invented 0 m when endpoint heights were missing. Profiles now use actual per-piece absolute endpoints. Missing heights suppress complete ascent, descent, profile and time instead of presenting partial height-dependent results as complete. Server time has the same missing-height rule.
- Coverage text now describes the least-covered individual property; it no longer wrongly implies that this is the union of all missing-property portions.

## Display

Only immutable z12 Terrain-RGB tiles are requested for 3D terrain: 36 PNGs, 580,346 bytes total (0.58 MB), instead of the full multiresolution pyramid. Assets are same-origin static files, not an external elevation API. They represent smoothed interpolation of Atlas network endpoint heights (roughly 25 m pixels locally), not a new measured DTM. Buildings use native terrain-aware extrusion; tree base elevations come from the same fixed coarse tiles. Terrain never replaces computational heights. Mode switching does not wait for tree placement or optional boundary sampling.

Display shadows have a dedicated worker and CanvasSource. No display graph load, PNG encoding, blob URL replacement or image redecoding on each time input. One in-flight frame and one latest pending frame bound the queue; a 1,000-event test checks this. Frames transfer ImageBitmap directly and release it after drawing. One canvas upload is requested per completed frame rather than an endless animation loop. Roof and wall projection matches the analytical existing model for concave/courtyard fixtures; tree display uses 32 crown samples. Raster size follows the viewport, capped at 2048 pixels on the long side. This is still a viewport-limited flat-ground geometric shadow model draped over display terrain: no terrain shadowing or roof detail is inferred. Frame rate and visual acceptance require actual WebGL/browser evidence; unit timing is not an FPS guarantee.

Cloud-dependent visual opacity has a visible 0.22 floor and 0.38 maximum in daylight; geometry is hidden at solar altitude <=2 degrees. Routing solar weight remains unchanged. These are model shadows with readable contrast, not measured shadows under actual clouds.

A single right-side dock holds route/explore mode, 2D/3D, layers, location and fit. Basemap selection lives in its compact popup; Explore themes and POIs use icon grids with named inputs and hover/focus descriptions. The duplicate left Explore sidebar is removed. The route form remains available in Route mode.

## Security findings and limits

The public `dist` tree is the publishing boundary. An automated check rejects credential signatures, private-key files, environment files, databases/GIS source containers and source maps. The reviewed bundle legitimately exposes client algorithms, Atlas display data and the public routing API address. Browser DevTools cannot securely conceal any of these. No credential is required by, or embedded in, the reviewed client implementation. This pattern scan is not proof that arbitrary secrets can never exist.

Added an allowlisted CSP: scripts from self, blob workers, explicit providers for map/weather/geocoding, no objects, framing or form submissions. Inline styles remain allowed because map transforms require them; inline scripts and eval are not allowed. Added camera/microphone denial, same-origin geolocation and framing restrictions. Existing nosniff and referrer restrictions remain. Provider names, URLs and publicly credited author names are not credentials. Address-result text and feature values use textContent rather than untrusted HTML. Geocoding cache and query length are bounded. Existing data fetch caches, concurrency limits, request cancellation and stale-response rejection remain.

No VM source, PostgreSQL permission settings, firewall, SQL query implementation or service-level rate limiter was available for server-side review. This work therefore does not certify the Oracle API against SQL injection, denial of service or unauthorized database access. Client changes cannot protect a directly reachable origin from attacks. Server work must enforce coordinate/input bounds, statement/request timeouts, bounded concurrency, per-client quotas, minimum DB privileges, access logging without sensitive query retention, OS updates and firewall/TLS configuration. The route endpoint is public by design; hiding its address in JavaScript is not a protection.

## Server profile status and SSH

Only standard Direct currently runs through Oracle API 0.2. The other mobility profiles and Shade/Sun still use the browser graph. `server-profile-contract.mjs` is preparation, not an installed server implementation. Frontend, static assets, menus and these display/metric changes do not need SSH. Installing the full profile API and verifying origin rate limits, DB permissions or firewall needs access to the actual VM/service or an equivalent authorized deployment path.
